# Чат MAX на GREEN-API

Тестовое задание на позицию «Фронтенд разработчик React»: веб-интерфейс для отправки и получения
текстовых сообщений в мессенджере MAX через [GREEN-API](https://green-api.com/max). Внешний вид — по
образцу [web.max.ru](https://web.max.ru/), светлая и тёмная тема берутся из настроек системы.

**Демо:** https://fry-alt.github.io/green-api-max-chat/

## Как пользоваться

1. Войдите с `idInstance` и `apiTokenInstance` из [личного кабинета GREEN-API](https://console.green-api.com).
   Адрес API подставляется сам по первым цифрам `idInstance` (инстанс `3100…` → `https://3100.api.green-api.com`),
   его можно поправить вручную.
2. Введите номер получателя (`+7…` или `+375…`) — откроется чат.
3. Напишите сообщение и нажмите Enter (Shift+Enter — перенос строки).
4. Ответ собеседника из MAX появится в чате. Сообщения от новых собеседников сами создают чат в списке.

### Настройка инстанса

Инстанс должен быть авторизован (QR-код в личном кабинете), а в его настройках:

- поле **webhookUrl пустое** — иначе GREEN-API не отдаёт уведомления через HTTP API;
- включено **«Получать уведомления о входящих сообщениях и файлах»** (`incomingWebhook`);
- по желанию — уведомления о сообщениях, отправленных с телефона (`outgoingMessageWebhook`):
  тогда в чате видны и ответы, написанные в самом приложении MAX.

Если что-то не так, приложение скажет об этом при входе или в плашке над списком чатов.

## Запуск локально

Нужен Node.js 20.19+ или 22+.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # unit-тесты (Vitest)
npm run build      # сборка в dist/
```

## Как устроено

| Файл | Что делает |
|---|---|
| `src/api/greenApi.ts` | Клиент GREEN-API: `getStateInstance`, `getSettings`, `checkAccount`, `sendMessage`, `receiveNotification`, `deleteNotification`. Коды ошибок переводит в понятный текст |
| `src/lib/poller.ts` | Цикл получения уведомлений: `receiveNotification` → обработка → `deleteNotification` |
| `src/lib/notifications.ts` | Достаёт из уведомления текстовое сообщение личного чата |
| `src/state/chats.ts` | Состояние чатов — чистый reducer, покрыт тестами |
| `src/components/` | Экран входа, список чатов, окно переписки |

**Отправка** — методом [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/). Чат создаётся
через [CheckAccount](https://green-api.com/v3/docs/api/service/CheckAccount/): в MAX v3 идентификатор чата —
число, а не номер телефона, и по нему же потом приходят ответы. Сообщение сразу показывается со статусом
«отправляется», после ответа API — с галочкой; при ошибке его можно отправить повторно.

**Получение** — по [технологии HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/):
long polling с `receiveTimeout=20`, чтобы не дёргать сервер впустую. Важные детали:

- уведомление удаляется из очереди, даже если его не удалось разобрать, — иначе очередь встанет;
- если не удалось удалить, уведомление придёт ещё раз, поэтому сообщения дедуплицируются по `idMessage`;
- эхо нашего же сообщения (`outgoingAPIMessageReceived`) может прийти раньше ответа `sendMessage` —
  reducer это учитывает, дубля не будет;
- при обрыве связи цикл повторяет запросы с нарастающей паузой (1 → 2 → 4 … 15 с), статус виден в шапке;
- при выходе или смене инстанса запрос обрывается через `AbortController`.

**Хранение.** Данные доступа и переписка лежат в `sessionStorage`: переживают перезагрузку вкладки,
но стираются при её закрытии. Токен никуда, кроме GREEN-API, не отправляется. Бэкенда нет —
GREEN-API разрешает запросы из браузера (CORS).

### Ограничения

- Только текстовые сообщения в личных чатах — так требует задание. Файлы и группы пропускаются.
- Очередь уведомлений у инстанса одна: если открыть чат в двух вкладках, сообщения разойдутся между ними.
- История переписки до входа не подгружается — видно только то, что пришло в очередь (она хранится 24 часа).
